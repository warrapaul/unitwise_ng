These logs show a reconnect loop caused by a STOMP subscription that the server rejects.

What’s happening, step by step (repeats every ~3 seconds):

The Angular client (origin: http://localhost:4200) opens a WebSocket to ws://localhost:8080/api/ws?token=... using the STOMP subprotocols (v12.stomp, v11.stomp, v10.stomp).
Your Spring Boot backend accepts the upgrade (Status: 101, which is the correct “Switching Protocols” response, so the handshake and JWT auth are fine; the session is even tied to user=2).
Right after connecting, the client subscribes to /agency/1.
The broker responds with a STOMP ERROR frame: Invalid destination ... '/agency/1' is not a valid topic destination.
An ERROR frame makes the server close the connection, so the client’s auto-reconnect kicks in about 3 seconds later, and the cycle repeats with a new session ID each time.

Root cause: the destination /agency/1 doesn’t start with any prefix your broker is configured to handle. In Spring, enableSimpleBroker(...) only accepts subscriptions for the prefixes you register. For example, if you have:

java
registry.enableSimpleBroker("/topic", "/queue");
registry.setApplicationDestinationPrefixes("/app");

then /agency/1 matches nothing, so it’s rejected.

Fixes (pick one):

Client side (usually the right one): subscribe to a destination under an existing broker prefix, e.g. /topic/agency/1.
Server side: add the prefix to the broker config, e.g. enableSimpleBroker("/topic", "/queue", "/agency"), and make sure whatever publishes messages (SimpMessagingTemplate.convertAndSend("/agency/1", ...)) uses the same destination.
