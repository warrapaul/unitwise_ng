
Agency and Building Module: UI/UX Review

Global issues from the Tenants review (contrast, 11-12px text, touch targets under 44px, nested cards, US date format, placeholder-as-value, “Optional” clutter, missing confirmations, missing loading/empty/error states) also apply here and are not repeated in full. Module-specific issues are below.

A. Inheritance model (agency → building → room)

This is the biggest gap. The override rule is not visible anywhere in the UI.

Show a source badge on every inheritable value: “Agency default”, “Building override”, “Room override”. Only the building contract details do this 
MOST FIELDS ARE DEFAULTS ONLY SHOW BADGES FOR OVERRIDEN VALUES - I.E THOSE OVERRIDEN AT ROOM LEVEL OR AGENCY DETAILS OVERRIDEN AT BUILDING LEVEL

Use one badge component and one set of terms everywhere. Currently “Agency default”, “Not configured” and “Uses the agency’s PayBill” are all in use.
Apply the badges to rent terms, charges, M-Pesa, contract details, and the contract template, not only contract details.
Every overridden field needs a “Reset to agency/BUILDING default” action. None exists.


Show the effective value at building and room level with its source, e.g., “KES 25,000 · from agency”.
The Create building form (Image 4) opens with blank rent fields even though the agency has defaults. PREFILL WITH a hint,  “InheritED from agency” , so a blank field is not read as zero.

Building Monthly charges does not list inherited agency charges. Show them in the same list, marked “Inherited”, with an “Override” action.

The “Contract template” button opens the same-looking screen at agency and building level. Show the level, the scope, and what is being overridden at the top.
B. Module-wide issues
The header switcher shows “Baobab Heights” while the user is on the agency page, Edit building for Acacia Court, and the Agencies list. Make it reflect the current context or hide it on admin screens.
The notification badge (“13”) overlaps and clips the property switcher on narrow widths (Images 3, 4, 7, 12, 13). Fix the header layout.
The back button is a bare chevron “‹” with no label. Add a label or an accessible name.
Titles are truncated (“Agency contract te…”). Shorten or wrap them.
The bottom nav is present on some agency screens and missing on others (Images 1, 2, 5, 12 vs. 3, 8). Be consistent.
Agency detail and building detail are single endless pages with 8+ stacked sections. Add tabs, a sticky section nav, or collapsible sections (Overview, Buildings, Billing, People, Payments, Contract, Addresses).
Edit forms open inline inside the long page and push content down. Move them to separate screens or bottom sheets with a pinned action bar.
Several screenshots show clipped cards and blank gaps (Buildings list, Monthly charges, M-Pesa header, Administrators). If these are not capture artifacts, fix the rendering.
Sections do not use a consistent header pattern. Some have an icon-only pencil, some a text button, some a trailing link.

Destructive buttons (Delete, Remove, Stop) look the same weight as normal actions. Differentiate them and add confirmations.

Monospace is used inconsistently for values (registration number, ID, phone, email). Use one value style.
Label-value rows use different label widths per card. Standardize the alignment.
Terminology: Agency / Landlord / Owner / Administrator / Admin are mixed.
“Registration”, “Registration number”, “LR number” and “Registration -” are all used. Define each term once.
“Unitwise ID” is used here, while “UnitWise ID” appeared in the Tenants module.
“Arrears generation day” (create form) and “Bills created on day” (detail) are the same field with different names.
“Payment due day: 5” needs a suffix (“5th of each month”). “Late fee KES 500” needs a unit (once, daily, or monthly). “Grace period 3 days” is fine.

KPI cards do not look tappable. Make them link to the relevant list.
“Open repairs: 0 · Not yet closed” has no destination or module.

Billing workflow

The alert is a large block inside the card. Use a single prominent CTA for the next step.
“Generate bills” is already done and takes the same space as the active step. Collapse completed steps.

Floors and rooms

The full list of 12 rooms is always expanded, making the page very long. Collapse floors by default with a summary (“4 rooms · 1 occupied”).
Each floor header has “+” and a trash icon side by side, unlabeled and ~32px. Risk of accidental deletion. Put them in an overflow menu, and add a confirmation that explains what happens to rooms and tenants.
Floor names are lowercase (“floor1”). Use “Floor 1”.
“Add floor” and the per-floor “+” are ambiguous. Label “Add room”.
Room rows show only name, rent and a status pill. Add tenant name, lease status and balance.
“Vacant” is green and “Occupied” is grey, which inverts expectations. Vacancy is not positive. Use neutral/orange for vacant.
Rows do not look tappable. Add a chevron.
The room rent does not show whether it is the building default or an override.
No search, filter (vacant/occupied), or bulk edit for rooms.
Cannot see rooms with arrears.

R. States, security and accessibility
